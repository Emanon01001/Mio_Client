# Mio Client

![Mio Client](assets/mio-mark.svg)

**自分らしいプレイを、もっと自由に。**

Minecraft Bedrock（Windows x64 / GDK版）向けのRustクライアントです。
ゲーム内メニューは**機能名が英語、説明・設定が日本語**、**Mio Launcherは英語UI**です。
解析・実機確認の対象は **1.26.6301.0 x64 / 1.26.65.1 x64**。その他のビルドは[更新時の互換性判定](#features-ゲームが更新されたとき)に従います。

## クイックスタート

Windows x64のRust MSVCツールチェーン、Visual Studio Build ToolsのC++ビルド環境、Windows SDKを用意し、ルートで実行します。

```powershell
cargo build --release --workspace
.\target\release\mio_launcher.exe
```

1. Mio Launcherの**Launch Game**でMinecraftを起動し、**Inject Client**でDLLを読み込みます。
2. ゲーム内で**L**を押すとメニュー・コンソールを開閉できます。
3. 機能を選び、詳細設定を変更します。保存する場合は**プロファイル・保存**を使います。
4. **END**、ゲーム内の終了ボタン、またはランチャーの**Eject**でクライアントを解除します。

成果物は`target/release/`です。DLLは`Mio_Client.dll`、設定は`Mio_Client.toml`です。旧名（`mcbe_client.toml`など）の設定は、初回起動時に新しい名前へ自動で引き継ぎます。
設定・プロファイル・ログはDLLの隣へ保存します。DLL差し替えと設定退避は[出力先と設定の扱い](#build-出力先と設定の扱い)を確認してください。

メニュー（ClickGUI）の初期キーは`L`です。メニュー上部の**ClickGUIの設定 → メニューを開くキー**から変更できます。変更はDLLの隣の`Mio_Client.toml`の`[gui] menu_key`へ自動保存され、再注入後も有効です。他の設定やコメントは保持します。終了キー・未割り当て・通常のマウスボタンは使用できません（MOUSE4・MOUSE5は使用可能です）。

各キー選択欄の**キーを押して設定**をクリックすると入力待ちになります。割り当てたいキーを押して設定でき、左右のShift・Ctrl・AltやMOUSE4・MOUSE5も区別します。**Escでキャンセル、Backspaceで割り当て解除**です。入力待ち中とキーを離すまでは、ClickGUIの開閉・終了キーの誤動作を防ぎます。従来の一覧選択も使えます。

チャットや入力欄で文字を入力している間は、Lなどの文字キーを文字として扱います。ClickGUIは**Escでも閉じられます**。一覧などのポップアップ表示中は先にその表示を閉じ、キー設定中は入力待ちだけをキャンセルします。HUD配置編集中のEscはメニューへ戻ります。開閉キーで閉じる場合は、入力欄以外をクリックしてから押してください。

<a id="build"></a>

## ビルドとランチャー

Windows x64で実行します。RustのMSVCツールチェーンとVisual Studio Build ToolsのC++ビルド環境、Windows SDKが必要です。

以下のコマンドはプロジェクトのルートから実行します。

<a id="build-リリース版"></a>

### リリース版

```powershell
cargo build --release --workspace
.\target\release\mio_launcher.exe
```

コマンドラインから操作する場合は、必要なコマンドを実行します。

```powershell
.\target\release\mcbe_injector.exe launch  # Minecraftを起動
.\target\release\mcbe_injector.exe inject  # 起動後に注入
.\target\release\mcbe_injector.exe eject   # 解除
```

`mio_launcher.exe`をダブルクリックするとMio Launcherを開きます。以前の`mcbe_injector_gui.exe`も同じ画面を開く互換用の入口です。
英語UIで対象プロセスの状態（Not running / Ready / Injected）を1秒ごとに表示し、**Launch Game**・**Inject Client**・**Eject**で操作します。
DLL は既定で同じフォルダの `Mio_Client.dll` を使い、**Browse…**で変更できます。
GUIはダークテーマで、英字にはSegoe UI、日本語を含むパスには日本語フォントを使います。ウィンドウはサイズ変更でき、小さい画面では縦にスクロールできます。
ゲーム内UIと共通のMioロゴ、ラベンダーとミントの配色を使用します。
対象プロセス名の変更は**Advanced settings**から行います。DLLが見つからない場合や操作の処理中は注入ボタンを無効にし、結果とエラーを画面内に表示します。

注入するとゲーム画面にオーバーレイ (hudhook / Dear ImGui) が出ます。
L メニューの中にコンソール (ログ表示とコマンド入力) があります。

<a id="build-出力先と設定の扱い"></a>

### 出力先と設定の扱い

標準の出力先は`target/release/`です。別フォルダへ出す場合は以下を使います。

```powershell
cargo build --release --workspace --target-dir target/staging
.\target\staging\mcbe_injector.exe inject --dll D:/Programming/Rust/Mio_Client/target/staging/release/Mio_Client.dll
```

`--dll`には自分の環境のDLLの絶対パスを指定します。
使用中のDLLがある出力先へ再ビルドする場合は、先にejectしてDLLが解放されたことを確認します。
timerの時刻補正などでDLLが残る場合はゲームの再起動が必要です。
別の出力先でビルドしただけでは、ゲーム内のDLLは切り替わりません。

`Mio_Client.toml`・`profiles/`・キー割り当て・ウェイポイント・ログはDLLの隣に保存されます。
別のフォルダから注入すると、そのフォルダの設定を使います。`client/default_config.toml`は初回生成のテンプレートです。
保存した設定を保持する場合は、`target/`全体を削除する`cargo clean`の前に退避してください。

<a id="build-検証"></a>

### 検証

プロジェクトのルートで実行します。

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
cargo check -p client --no-default-features --all-targets
```

依存関係を取得済みの環境ではbuild・test・check・Clippyに`--offline`を指定できます。
Clippyでは`--`の前に付けます。
既定の`entrypoint`を無効にした検証は、[SDKを別DLLへ組み込む構成](#sdk)を確認します。
オフラインのゲームexe照合とベンチマークは解析資料（ローカルの`analysis/README.md`）を参照してください。

VS Codeでは`Ctrl+Shift+B`がリリースビルド、`Tasks: Run Test Task`がワークスペースのテストです。
`Tasks: Run Task`からClippyとfmtの確認も実行できます。

<a id="build-ゲーム更新時の照合"></a>

### ゲーム更新時の照合

**Mio Signature Checker**で、ゲームを起動せず、更新前後の実行ファイルを読み取り専用で照合できます。実行にPythonは不要です。

```powershell
cargo build --release -p signature-checker
.\target\release\mio_signature_checker.exe
```

1. **参照…**で確認したい`Minecraft.Windows.exe`を選び、**検証を開始**を押します。
2. 一致数・RVA・用途コメントと、命令・アドレス・フィールドの整合性を確認します。名前や用途で検索し、未検出・複数候補・基本機能・任意機能などで絞り込めます。
3. **JSONを保存…**で更新前の結果を残します。更新後は「比較用JSON」に指定し、一致数・RVA・パターン定義の変化を比較できます。

**全結果をコピー**で全シグネチャ・整合性検証・差分をテキストとして、**JSONをコピー**で従来のJSON形式としてクリップボードへコピーできます。シグネチャ行の**コピー**、または名前・RVAの右クリックから、名前・ワイルドカード付きパターン・全候補のRVA・行全体を個別にコピーできます。整合性検証にも各項目の**コピー**があり、判定・説明・全フィールド値を取得できます。

EXEをウィンドウへドロップするか、`mio_signature_checker.exe`のアイコンへドロップしても確認できます。
ファイル読み込みと走査はワーカーで実行し、ゲームの起動・DLL注入・対象ファイルへの書き込みは行いません。
レポートは`.json`へ新規保存し、既存のEXE・比較用JSON・レポートを上書きしません。

自動化にはコンソール版を使います。ファイル名は未使用のものを指定してください。

```powershell
.\target\release\mio_signature_checker_cli.exe --exe 'C:/XboxGames/Minecraft for Windows/Content/Minecraft.Windows.exe' --out before.json
# Minecraft更新後（同じツール・同じシグネチャ一覧で比較）
.\target\release\mio_signature_checker_cli.exe --exe 'C:/XboxGames/Minecraft for Windows/Content/Minecraft.Windows.exe' --baseline before.json --out after.json
```

| 結果・終了コード | 意味 |
|---|---|
| `STATIC CHECKS PASSED` / 0 | 記録済みのPE識別値に該当し、静的な照合を通過。実ゲームのABI・全機能の動作保証ではありません。 |
| `ISSUES FOUND` / 1 | 未検出や命令・フィールドの検証失敗あり。基本機能／アドレス導出／任意機能を区別して確認します。任意機能の失敗だけでクライアント全体が非対応とは断定しません。 |
| `REVIEW REQUIRED` / 2 | 未解析ビルド、解消できない複数候補、未検証ABIなど。すべてのシグネチャが一致しても、新しいビルドは要確認です。 |
| 入力・I/Oエラー / 3 | 不正・対象外形式のPE、読み込み失敗、比較JSONの形式違い、保存先が既存ファイルなど。 |

現行の80件は`client/src/signatures.rs`と同じ定義をコンパイル時に取り込みます。GUI上部に、このEXEが取り込んだ定義数を表示します。シグネチャを修正したら検証EXEも再ビルドしてください。
一致数は256件までを保持し、上限に達した場合は`256+`と表示します。複数候補は、設定ID・参照フィールドなどとの照合で絞り込める場合があります。
クライアントと共通の処理で7個のアドレス、スキンのフィールド、設定IDを検証し、位置・効果・採掘進捗の整合性も確認します。Freecam用にはカメラ位置とquaternionのコピー位置、描画原点・複製先のXYZ対応、直前の関数プロローグも確認し、合計17項目の静的検証を行います。
RVAの移動自体は異常とは限りません。パターンの変更はバイナリの変化と区別して表示します。比較JSONでは、静的検証の追加・削除・判定変更・アドレスやフィールド値の変更も検出します。古いJSONも引き続き比較できます。
PE識別値はヘッダーのtimestamp・image size・checksumであり、ファイル全体の暗号学的な真正性確認ではありません。
比較にはこのEXEが保存したJSONを使用します。従来のPython版JSONは形式が異なります。EXEは最大1GiB、比較JSONは最大8MiBです。

PEの解析は[MicrosoftのPE形式仕様](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)を参照しています。
構造体・仮想関数・オブジェクト寿命など、ファイル上の照合だけでは確認できない項目は実機での検証が必要です。

ローカルの解析資料がある環境では、従来のPython版も利用できます（Python標準ライブラリのみ）。

```powershell
python analysis/tools/check_update.py --exe 'C:/XboxGames/Minecraft for Windows/Content/Minecraft.Windows.exe' --out .analysis-cache/compat/current.json
# 更新前のJSONを残しておくと候補数の変化を比較できます
python analysis/tools/check_update.py --exe 'C:/XboxGames/Minecraft for Windows/Content/Minecraft.Windows.exe' --baseline .analysis-cache/compat/previous.json --out .analysis-cache/compat/current.json
```

未検出があれば終了コード1を返します。複数候補は機能側の相互照合が必要です。
全シグネチャが一致しても、構造体・仮想関数・ネイティブABIの互換性は保証できません。
実行中は`compatdebug`で、起動時に共有走査した結果と各取得処理の判定を確認できます。
実装と検証範囲は更新耐性の記録（ローカルの`analysis/reports/update_resilience_2026-11-18.md`）を参照してください。

## 操作・HUD・設定

<a id="usage-日本語表示とフォント"></a>

### 日本語表示とフォント

機能名は`AutoSprint`・`InventoryHUD`・`Waila`などの英語表示です。
説明文・詳細設定の項目・状態表示・操作案内・通知本文・コンソールのヘルプは日本語のままです。
メニュー・機能一覧HUD・HUD編集画面・機能名を含む通知で共通の表示名を使います。
機能の検索は日本語名・従来の英語名の両方に対応します。機能名にマウスを合わせるとコマンド用の英語名を表示します。
`toggle autofish`などのコマンド名、ブロックID、保存済み設定のキーは従来どおりです。
チャット本文・プレイヤー名・ユーザーが付けたプロファイル名は、そのまま表示します。
診断コマンドの技術的な関数名・カウンター名も保持しています。

Windowsのメイリオを優先し、利用できない場合は游ゴシックMedium・MSゴシックを順に使います。
英数字と日本語を同じ書体で描き、文字の太さや基準線をそろえています。フォントの配布・ダウンロードは行いません。
文字サイズはDLLの隣の`Mio_Client.toml`で指定します。既存の設定ファイルでも既定16pxになります。

```toml
[gui]
font_size = 16.0
```

サイズは12～28pxです。20pxなどに変更した場合は再注入で反映します。フォントの読み込みは初期化時だけ行います。
別ウィンドウのコンソールもUnicodeで入出力し、システムのコードページを変更せずに日本語を扱います。

<a id="usage-オーバーレイ"></a>

### オーバーレイ

メニュー・コンソール・HUD編集画面と各HUDは、濃紺の背景・ラベンダーとミントのアクセント・角丸の共通デザインです。
機能一覧は左の機能名で詳細設定を開閉し、右のスイッチでON/OFFします。
検索・カテゴリ（移動／戦闘／ワールド／視界／HUD／その他）・並び順を組み合わせて絞り込めます。
検索欄と終了ボタンを残したまま、中央の一覧だけをスクロールできます。
長い機能名は省略表示し、マウスを合わせるとコマンド名を確認できます。
プロファイルの保存・読み込みは上部の **プロファイル・保存** を開いて操作します。
カテゴリや詳細の開閉状態はメニューを閉じても保持し、DLLの再読み込み時にリセットします。
既存の設定ファイル・プロファイル・コマンドはそのまま使用できます。

2026-11-16追加:

- `durabilityalert`：ホットバーの道具・装備した防具の耐久低下を通知。初期OFF、残り10%が既定。割合・監視対象・通知間隔は詳細設定で変更できます。
- `autofish`：自分の浮きのアタリを検出して回収し、任意で再投します。初期OFF。最初だけ釣り竿を手動で投げてください。再投は既定0.8秒後で、釣り竿の選択維持・予備耐久5超・他の自分の浮きがないことが条件です。`Require clear cast view`をONにすると、照準先が空中（水を除外）・6ブロック以内に既知の生物がいないことも要求します。浅瀬や草でも止まるため、この追加条件は既定OFFです。自分のインベントリを開いたままでも継続します（InventoryMoveのON/OFFには依存しません）。チャット・ポーズ・L・非フォーカス・ワールドでの手動右クリック・持ち替えでは中断します。`Require clear cast view`がONの場合は照準情報が古くなると再投を見合わせます。`fishdebug`で要求回数と、メニューを開く前の状態も確認できます。ComponentItem型の釣り竿の読取りを修正し、2026-11-16にユーザーが実ゲームで回収・再投の動作を確認しました。
- `coordinates`の詳細設定の **座標をコピー** で、現在地をクリップボードへコピーします。
- `blockesp`の詳細設定に **任意のブロックを指定** を追加。`diamond_block`や`*shulker_box`などのID・ワイルドカードを入力し、Add/Removeで編集できます。空白・カンマで複数追加、最大32件。ONの間は最後に照準を合わせたブロックを追加するボタンも出ます。**プロファイルの保存で対象リストも保存**します。Ores/ChestsをOFFにすると明示指定した種類だけを表示できます。読み込まれている範囲・設定半径が対象です。

AutoRefillはこの版には含めていません。同一インベントリ内の交換経路は後にDurabilityGuardで実装しています。
配置・イベント・未解決事項は 解析メモ（ローカルの`analysis/reports/item_helpers_2026-11-16.md`）、
オフライン照合は `python analysis/tools/verify_fishing.py` を参照してください。

機能一覧は検索欄の下の **並び順** で並び替えできます。`標準の並び順`（従来順）、
`名前（英字A→Z）`、`名前（英字Z→A）`、`有効な機能を先頭に`（有効な機能を先頭）、`種類別`（種類別）に対応します。
検索との併用ができ、種類別ではグループ見出しを表示します。並び順はメニューを閉じても保持しますが、
DLLの再読み込み時には標準の並び順へ戻ります。プロファイルの保存順や機能の実行順は変わりません。

- **L** でメニューを開閉。各機能の ON/OFF と、**詳細設定** 内の詳細設定、Eject ボタンがあります。検索欄で機能名を絞り込めます。
- **HUDの配置を編集** で表示位置を編集できます。枠をドラッグし、**編集を完了** または **Esc** でメニューへ戻ります。Lで編集画面ごと閉じられます。
- 編集対象は左上の一覧（`hud`）、コンパス、レーダー、Keystrokes、Target HUD、Vitals、PlayerAlert、Effects、Air、Waila、Armor HUD、Inventory HUD、Session Statsです。ワールド未接続・機能OFFでもプレビュー枠を移動でき、機能のON/OFFは変わりません。追加のHUDも配置編集のパネル一覧から選択できます。
- 枠が重なる場合は **編集するパネル** で選び、**選択中のパネルだけを表示** をONにします。**8ピクセル単位で移動** で8px単位の移動、X/Yで数値調整、**初期位置に戻す** で選択した枠を組み込み初期位置へ戻せます。
- 編集画面の **プロファイルに保存** で位置を含む現在の設定を保存できます。再起動後は同じ名前を **プロファイルを読み込み** で読み込んでください。従来のプロファイルも使用できます。
- 右端・下端を基準にしていたHUDはドラッグ後もその基準を保ちます。コンパスは中央からのX／上からのY、Wailaは画面中央からのX/Yです。照準やワールド内の枠はこの位置編集の対象外です。
- メニュー表示中はキー・マウス入力をゲームに渡さず、autosprint / autoclicker も止まります。
- コンソール操作中の左クリックはネイティブの攻撃入力でも遮断し、開く前から続いていた攻撃・破壊入力も解除します。
- 表示中はゲームへ渡すマウスの視点移動量も遮断します。閉じた直後はマウス位置の基準を合わせ直し、表示中のカーソル移動による視点の飛びを防ぎます。
- メニュー・コンソール・HUD配置編集を開いている間は、全ネイティブマウスイベントと未処理の入力キューも遮断します。ホイールでゲーム側のホットバーや画面が動くことを防ぎ、閉じると通常操作へ戻ります。常時表示のHUDだけならゲーム操作は遮断しません。
- 左上に有効なモジュールの一覧を常時表示します (`show_hud = false` で消せます)。
- 一覧は角丸の半透明カードで、機能名と現在の状態を分けて表示します。ヘッダーに表示対象の件数を出し、移動可能・未接続などの状態をバッジで示します。長い状態は機能名の下へ省略せずに折り返します。既定の縦1列表示では全行を常時表示し、列表示で画面に収まらない場合は「ほか○件」と表示します。
- 既定では **コンパクト表示**（行の高さ・余白を詰める）と **待機中の機能を隠す**（「未接続」「データ待ち」「待機中」の行を出さず、ヘッダーに「表示数件 · 待機N」と出す）が有効です。`hud`の詳細設定、または `[gui] hud_compact / hud_hide_idle` で従来の表示に戻せます。
- 一覧が長くなると、画面の高さの45%に収まるように自動で最大3列に分けて表示します（1列目の上から下へ並べ、続きを次の列へ）。`hud`の詳細設定「列の数」または `[gui] hud_columns` で1〜3列に固定できます（0で自動）。
- 一覧の初期位置は `[gui] hud_x / hud_y` でも指定できます。稼働中は`hud`の詳細設定で移動・ON/OFFでき、プロファイルにも保存されます。FPSや座標などの一覧内の行は、一覧全体として移動します。
- 描画APIは `renderer = "auto"` で自動判定します (d3d12.dll がロードされていれば DX12)。
  オーバーレイが出ない場合は `"dx11"` / `"dx12"` を指定してください。
- メニューと一緒に **console** ウィンドウが開きます。下の入力欄にコマンドを入れて Enter で実行します。
- ClickGUIとコンソールのウィンドウの大きさ・位置は、DLLの隣の`Mio_Client_windows.toml`に保存し、次回の起動時に同じ大きさ・位置で開きます（変更後1秒で保存、終了時にも保存。画面が小さくなった場合は画面内に収めます）。このファイルを削除すると初期配置に戻ります。
- `[gui] console_window = true` で、従来の別ウィンドウのコンソールも開きます。
- `[gui] enabled = false` でオーバーレイなし (別ウィンドウのコンソールのみ) になります。
  オーバーレイを開始できなかった場合も、別ウィンドウのコンソールが開きます。

プロファイルの保存・切り替えと詳細設定の項目は[コマンドガイド](#commands)を参照してください。

<a id="usage-設定"></a>

### 設定

<a id="usage-triggerbotkillauraの攻撃設定"></a>

#### TriggerBot・KillAuraの攻撃設定

**TriggerBot** は初期OFFです。`toggle triggerbot`、またはメニューからONにします。
既定は射程3ブロック・毎秒8回・モブのみ。照準に当たる最も手前のエンティティが対象条件を満たしたときだけ、通常の攻撃処理と腕振りを実行します。
対象外のエンティティに照準が当たっている場合、その奥の相手を代わりに攻撃しません。
詳細設定で攻撃頻度とプレイヤー／モブの対象を変更でき、`set triggerbot 3`で射程を設定できます（1～6ブロック）。

**KillAura** の詳細設定には以下を追加しました。既存設定の動作を維持するため、既定は360度・壁判定OFF・長押し限定OFFです。

- **攻撃対象の視野角**：視線を中心とした角度で対象を絞ります。360度で全方向です。
- **壁越しに攻撃しない**：各対象の手前にブロックがあれば、その対象への攻撃を見送ります。
- **左ボタン長押し中だけ動作**：ゲームの攻撃ボタンを押している間だけKillAuraを動作させます。
- **1周期の最大対象数**：既定8体、1～16体。各周期で近い対象から順番に、対象ごとに1回攻撃します。1にすると従来の単体攻撃に戻ります。CPSは周期の頻度で、腕振りは1周期に1回です。設定はプロファイルにも保存されます。

`auradebug`の`last cycle attempts / accepted / limit`で、直近の周期に何体へ攻撃を要求し、何回ゲームの攻撃処理が成功を返したかを確認できます。`accepted`はサーバー上での実ダメージの保証ではありません。

自動攻撃の優先順位は **KillAura → TriggerBot → AutoClickerの繰り返し** です。長押し限定のKillAuraが待機中ならTriggerBotが動作できます。
手動の通常攻撃は維持します。メニュー・チャット・インベントリ・非フォーカス、食事や釣りの使用中は自動攻撃を停止します。
ゲーム自身の攻撃許可・無敵時間などの判定は維持します。

TriggerBotは必ずブロックによる遮蔽を調べます。読み込めない場所は遮蔽物として扱い、水・溶岩は通します。
ブロック単位の判定なので草・柵・ガラスなども遮蔽物になります。第三者視点のカメラ位置を使う判定は追加していません。
設定はプロファイルへ保存できます。`triggerdebug`（`auradebug`と同じ）で動作元・対象・攻撃／成功／腕振りの合計回数を確認できます。

<a id="usage-autoweaponfriends"></a>

#### AutoWeapon・Friends

どちらも初期OFFです。メニューの戦闘カテゴリ、または `toggle autoweapon`・`toggle friends` で有効にします。

**AutoWeapon** はエンティティへの攻撃直前に、ホットバーから通常素材の剣を選びます。素材の優先順はネザライト・ダイヤモンド・鉄・石・木／金です。同じ優先度なら現在の武器を維持します。設定で剣がない場合の斧も許可できます。エンチャント・アドオンの攻撃力比較は行いません。通常インベントリからは移動せず、選択後のスロットを維持します。
残り耐久が設定した下限以下の武器を除外します。DurabilityGuardが有効ならその設定値も下限に使います。採掘には反応せず、食事・道具の自動選択・釣り・耐久保護の交換中は持ち替えません。

**Friends** は表示名を完全一致で登録し、KillAura・TriggerBot・AutoClickerの連打から除外します。英字の大小は区別せず、名前の空白と日本語はそのまま扱います。手動の単発攻撃は維持します。プレイヤー名が取得できない場合も自動攻撃を見送ります。TriggerBotでは友達の奥にいる相手へ攻撃を通しません。

```text
friends add Steve
friends add 日本 太郎
friends list
friends del Steve
friends clear
```

詳細設定の名前リストでも追加・削除できます。最大32人・1人64文字です。アカウントIDではなく表示名による保護なので、同じ表示名のプレイヤーはすべて保護します。名前リストとAutoWeaponの設定はプロファイルに保存できます。

<a id="usage-mininghuditemcounter"></a>

#### MiningHUD・ItemCounter

どちらも初期OFFです。メニューからON、またはコンソールで実行します。

```text
toggle mininghud
toggle itemcounter
```

**MiningHUD** は採掘中のブロック名・破壊進捗・座標を表示します。割合はゲームの現在値を読み取り、時間から推定しません。
詳細設定で座標表示・待機中の非表示を変更できます。瞬時に壊れるブロックでは途中の進捗を表示できない場合があります。

**ItemCounter** は通常インベントリとホットバー（最大36スロット）の同じアイテムIDの個数を合計します。
既定の対象は`arrow`・`torch`・`bread`で、手持ちアイテムも先頭に追加します。同じ対象は重複表示しません。
詳細設定の対象アイテム欄にIDを入力して **追加**、または **手持ちを追加** を押します。
空白・カンマ区切りで最大16種類を指定でき、`minecraft:`は省略できます。
「ホットバーだけ数える」「手持ちアイテムも数える」「所持数0も表示」を変更できます。
チェスト・装備中の防具は数えません。同じIDのアイテムは耐久値やNBTが異なっても合計します。

どちらも **HUDの配置を編集** で移動でき、位置・表示項目・ItemCounterの対象リストはプロファイルに保存されます。

<a id="usage-照準先の情報waila"></a>

#### 照準先の情報（Waila）

`toggle waila`、または一覧の **Waila** でONにすると、照準の線に当たる最も手前のブロック／エンティティをカードで表示します。
ブロックの種類名・座標・距離、エンティティの表示名（なければ種類名）・当たり判定下端の中心座標・距離・取得できる体力を表示します。
距離は視点からブロック／当たり判定の手前側までの距離です。何も当たっていなければカードは表示しません。

- 詳細設定の **エンティティも表示** をOFFにすると従来のブロック表示だけになります。
- **座標と距離**、**体力**、**種類IDも表示** を個別に変更できます。体力不明の対象には体力行を出しません。
- 検出距離は既定6ブロック、1～64ブロック。`set waila 12` などでも変更できます。
- 水・溶岩で止めるかは従来の設定を引き継ぎます。ブロックで遮られたエンティティは表示しません。
- **HUDの配置を編集**、または詳細設定の横・縦位置で移動できます。プロファイルに保存できます。

エンティティは既存の読み取りスナップショット（最大1,024件）を使用します。ブロックは既存と同じボクセル単位の判定で、草・柵等の細かい形状や第三者視点のカメラ位置をゲームの選択判定と完全には再現しません。
ワールド内の変更、攻撃、インタラクトは行いません。

初回注入時に DLL と同じフォルダへ `Mio_Client.toml` が生成されます
(内容は [client/default_config.toml](client/default_config.toml))。変更は再注入で反映されます。

<a id="usage-バイトパッチ"></a>

#### バイトパッチ

メモリ書き換え系の機能は `[[patch]]` で追加します。シグネチャはゲームのバージョンに
依存するため同梱していません。自分で用意したシグネチャは、ゲームを起動せずに検証できます:

```powershell
.\mcbe_injector.exe scan "48 8B 05 ?? ?? ?? ?? F3 0F 10"
```

一意 (1 match) でないシグネチャは注入時に拒否されます。

<a id="features"></a>

## 機能ガイド

HUDの機能一覧は、機能名と状態が収まる範囲で列幅を自動調整します。長い状態文は機能名の下へ折り返し、折り返した行の高さを含めて最大3列へ分けます。列ごとに描画を制限し、隣の列へ文字がはみ出すのを防ぎます。L → HUD → Detailsの「コンパクト表示」「列の数」で調整できます。「待機中の機能を隠す」がONのとき、ヘッダーの「待機」は隠した件数です。複数列でも高さに収まらない場合は末尾に「ほか N 件」を表示します。文字幅と折り返し位置は、内容・フォント・画面サイズなどが変わったときに更新します。

「縦1列表示」は初期ONです。左側の1列に全行を常時表示します。機能名と状態が半分の幅に収まる短い行（FPS・時計・CPSなど）は、並び順を保ったまま2つずつ横に並べて高さを節約します（35機能・1280×720・16pxで高さ約514px）。それでも画面の高さが足りない場合だけ、収まる最大の大きさまで一覧内の文字サイズを調整します。スクロールやページ切り替えは使いません。Detailsの「縦表示の幅（px）」で幅を200〜800pxに指定できます（既定360px）。横幅に余裕を持たせると折り返しが減り、文字サイズを保って表示できます。「縦1列表示」をOFFにすると従来の自動・固定列数を使えます。幅・縦表示はProfilesへ保存できます。設定ファイルは`[gui] hud_vertical = true`・`hud_width = 360`です。一覧の描画だけ文字サイズを調整し、メニュー・他のHUDの文字サイズは変えません。

一覧の再現用描画・CPU計測は `cargo test -p client --release --lib hud_overflow_paint_cost -- --ignored --nocapture` で実行できます。35機能を使い、キャッシュなし・FPSだけ更新・キャッシュあり・縦1列を比較します。これはクライアント側の描画データ生成時間で、ゲーム全体やGPUの負荷ではありません。

<a id="features-performanceprofiler処理負荷の計測"></a>

### PerformanceProfiler（処理負荷の計測）

L → HUD → **PerformanceProfiler**をON、または`toggle performanceprofiler`で計測を開始します。初期OFF・キー未割り当てです。
機能ごとの更新・描画と、エンティティ取得、BlockESP、地形、明るさ、所持品などの共有処理を計測します。
HUDは合計時間が大きい順に表示し、Detailsでは全件表示・並び替え・停止/再開・リセット・結果のコピーができます。
HUDの配置編集に対応し、表示行数（5〜24）・集計間隔（200〜5000ms、初期1000ms）・位置をプロファイルへ保存できます。

| 列 | 意味 |
|---|---|
| 平均ms | 直近の集計区間内で、1呼び出しにかかった平均経過時間 |
| 最大ms | 同区間内の最長の1呼び出し |
| ms/秒 | 同区間内の合計経過時間を1秒あたりに換算 |
| 回/秒 | 計測対象の呼び出し回数を1秒あたりに換算（無効機能の軽い更新処理を含む） |
| 件/秒 | BlockESP・地形はブロック読取数、LightOverlayは走査列数、Entity snapshot・Actor factsは出力件数。その他は0 |

`*`付きの全体時間は子処理を含みます。行同士を合計してCPU使用率に換算しないでください。
測定対象はクライアント内の経過時間で、ロック待機・OSのスケジューリング・計測の影響も含みます。GPU実行時間やゲーム本体の全処理は測定しません。
描画はImGuiの描画データ生成部分であり、GPUでの描画完了までの時間ではありません。
Timerの速度補正前の時計を使い、停止・再開・リセット後に古いサンプルが混入しないよう世代を検証します。
記録が競合した場合はゲーム・描画スレッドを待たせず、サンプルを破棄して欠測数を表示します。高い欠測率では値を過小評価します。

`profilerdebug`は直近の集計結果をコンソールとDLLの隣の`Mio_Client_profiler.txt`へ出力します。
計測を停止すると直近の結果を保持し、再開すると新しい区間から計測します。比較時は同じ場所・視点・設定で、メニューを閉じた状態の値を確認してください。

周囲にプレイヤー・NPCが多い場合に備え、Vitals・LowHealth・SDKのVitals購読は自分の属性だけを取得します。他の機能がエンティティ情報を必要とする場合は、従来どおり共通の100ms間隔で周囲の情報も取得します。表示名は現在の文字を毎回検証し、変更がなければ所有済みの文字列を再利用します。NameTagsは表示する文字・フォントが変わったときに文字幅を計測し、近い対象を選んだ後、その表示対象だけを整列します。エンティティ世代・名前・体力・距離の表示変化に追従し、消えた対象のキャッシュは破棄します。ESPの取得では1回の列挙内でメモリ保護の確認を共有し、更新間隔と世代検証を維持します。

Actor factsの回数・平均・最大は、実際に取得した回だけを記録します。旧版は取得しないフレームも回数に含めていたため、比較には`ms/秒`と`最大ms`を使ってください。自分の属性だけを取得する場合、出力エンティティ数は0です。

大きなゲームヒープでは、`VirtualQuery`による保護領域の照会自体が重くなることがあります。読み取りバッチは、最大16ページずつ[QueryWorkingSetEx](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-queryworkingsetex)で常駐ページの保護を検証し、その取得処理内だけで128ページ分を再利用します。無効・非常駐の結果、API失敗、大きな範囲では従来の領域照会へ戻します。各ページの読み取り権限とガードを検査し、次の取得処理やネイティブ操作へキャッシュを持ち越しません。表示対象・取得間隔は変更しません。

BlockESP・ミニマップ・照準先などのブロック読み取りは、取得先のポインターチェーンとブロック名の検証にもこの方式を使います。取得先は毎回たどり直し、ワールド・エンティティ世代・取得関数・高さ上限の検証を維持します。未読み込みでブロックが返らない場合は名前の照会を省きます。ミニマップは状態ロック取得後も更新時刻を確認し、同時に呼ばれた場合の重複走査を防ぎます。

再現用の模擬計測:

```powershell
cargo test -p client --release --lib actor_collection_cost -- --ignored --nocapture
cargo test -p client --release --lib name_tags_paint_cost -- --ignored --nocapture
cargo test -p client --release --lib large_heap_validation_cost -- --ignored --nocapture
cargo test -p client --release --lib block_binding_cost -- --ignored --nocapture
```

75体・512体のダミーのコンポーネント／名前を使います。Actor factsは周囲全体の取得と自分だけの取得、NameTagsは同じ描画処理でキャッシュを無効にした場合・有効の場合・カメラ移動中を比較します。これらはCPU側の合成テストであり、HiveでのFPS改善率やGPU負荷を示すものではありません。
`large_heap_validation_cost`は256MiBのコミット済み領域内の96か所を読み取る前の検証時間を比較します。常駐するページだけを少数用意し、ゲームの大きなヒープで領域照会が高コストになる状態を再現します。
`block_binding_cost`は256MiB内にワールド取得先のポインターチェーンを配置し、従来の領域照会とページ単位の検証で同じ取得結果になることと、検証時間を比較します。実ゲームの走査・描画時間とは別の合成計測です。

<a id="features-skinstealerスキン画像の保存"></a>

### SkinStealer（スキン画像の保存）

L → ワールド・所持品 → **SkinStealer**をONにし、一度Lを閉じて一覧を取得します。Detailsで対象を選び、**スキン用PNGに保存**を押してください。自分も一覧の先頭に表示します。初期OFF・キー未割り当てです。

保存先はDLLの隣の`skins`フォルダーです。通常スキンの64×32・64×64・128×128は元画像のまま保存し、モデルを判定できる場合は読み込み時に選ぶ腕幅を表示します。対応するPersonaは、モデルのUVと顔画像から幅広の腕（Steve型）の配置に組み直します。各面の画像密度に応じて64×64または128×128で保存します。顔のアニメーションは最初の画像を使い、帽子・上着・袖・ズボンの透過を維持します。`skins save self` / `skins save <一覧の16進ID>`もスキン用保存です。

元画像をそのまま残す場合は**元テクスチャを保存**または`skins raw self` / `skins raw <ID>`を使います。こちらは元の解像度・RGBAを維持しますが、そのままスキンとして読み込めるとは限りません。ファイル名に`_skin` / `_raw`を付けて区別し、既存ファイルは上書きしません。保存待機中は二重要求できません。取得できない場合はLとポーズを閉じ、一覧を更新してください。

対象はゲーム内で取得済みの、自分と周囲の実プレイヤーです。キャラクター画面のプレビューは除き、一覧は最大64人・通常500ms間隔で更新します。画素のコピーは保存要求時の1回だけで、PNG圧縮とファイル保存は描画・ゲームコールバック外の既存ワーカースレッドで行います。ワールド・エンティティ世代・スキンID・画像サイズを再検証し、古い選択や無効な画像は拒否します。`skindebug`で診断ファイルも保存できます。

Persona変換は頭・胴体・両腕・両脚と対応する上着の箱型メッシュが対象です。**独自の立体形状・マント・アニメーションは再現しません。** 未対応の形状、部品不足、不正なUVは変換エラーとして表示します。256×256アトラスの単純な縮小や切り抜きはしません。スキンの適用・アカウント変更・外部アップロードは行いません。新しい取得経路は1.26.6301.0 / 1.26.65.1 x64向けです。

<a id="features-debughudf3風デバッグ画面"></a>

### DebugHUD（F3風デバッグ画面）

**F3**でON/OFFできます。LのHUDカテゴリで**DebugHUD**を探すか、`toggle debughud`でも切り替えられます。初期OFFです。

- 左側: ワールド名・保存フォルダーID・難易度・現在地のバイオーム、小数座標、ネザー/オーバーワールドの換算座標、ブロック座標、チャンク座標・チャンク内位置、向き・角度、移動速度・速度成分、ディメンション、ゲーム内時刻・経過日数、オーバーワールドのスライムチャンク判定、取得済みエンティティ数、サウンド数。
- 右側: CPU名・論理プロセッサ数、検出したGPU名、描画API、画面サイズ、プロセスメモリ。その下に照準先のブロック名・座標・空/ブロックの光量、対象液体の種類・座標、エンティティ名・座標・距離・ID・取得できる体力を表示します。
- FPSとフレーム時間はオーバーレイの描画から取得します。メモリはプロセスのワーキングセットで、Javaのヒープ使用量ではありません。
- Detailsで照準先・表示環境・背景を切り替え、文字サイズ（0.75～3倍、既定2.5倍）・背景の濃さ（既定45%）・左右それぞれの位置を調整できます。HUD配置編集では左側をドラッグできます。設定と切り替えキーはProfilesで保存できます。

参考画像のように文字幅に合わせた半透明背景と影を付け、右側は各行を右揃えにします。画面が狭い場合は自動で縮小します。通常UIとは別に、同じ日本語フォントを32pxで用意し、大きな文字のぼやけを抑えます。表示中は機能一覧・Radar・CompassなどのHUDとWailaを一時的に隠し、F3で閉じると戻します。各機能のON/OFF設定は維持されます。WorldMapの操作は継続でき、マップ表示中はDebugHUDの描画を控えます。

既存のSDK・エンティティ・照準先スナップショットを再利用する読み取り専用機能です。座標などの文字列は毎秒10回、FPS行は毎秒4回更新します。ワールド名・時計はゲーム側のコールバックで毎秒5回、対象光量は最大毎秒10回で照準先の1セルだけを読み、チャンクの新規読み込みや広範囲の走査を追加しません。CPU/GPUの検出は描画スレッド外で初回だけ行います。

GPUは検出したハードウェア一覧で、ゲームが実際に使っているGPUの断定ではありません。描画APIはDirectX 11/12の区別で、12.1などの機能レベルは表示しません。新しいデータ取得は照合済みの2ビルド限定です。サーバー側で共有されないワールド名や保存フォルダーIDなどは取得できない場合があります。無効な参照・未ロード・期限切れの情報は「未取得」と表示します。

バイオームは足元の実座標から取得し、`minecraft:plains`などの識別名で表示します。対象液体は主層と副層を調べるため、水没したブロックも対象です。水・流れる水・溶岩・流れる溶岩を区別し、読み取りに成功して液体がない場合は`minecraft:empty（なし）`と表示します。既存のWailaの液体設定・到達距離は変更しません。液体の判定は既存のブロック単位のレイ走査に従います。

サウンド数はゲームが使用中のFMODから取得した、仮想チャンネルを含む再生数と実チャンネル数です。Java版の上限値を流用した`0/32`などの表示はしません。ワールド名・ID・難易度・バイオーム・サウンド数は最大毎秒5回、対象液体は毎秒10回の更新です。`worlddebug`には直前の取得値と経過時間も記録します。

<a id="features-safewalk耐久保護"></a>

### SafeWalk・耐久保護

どちらも初期OFFです。Lで検索してONにするか、`toggle safewalk` / `toggle durabilityguard`を実行してください。詳細設定の設定はプロファイルで保存できます。

| 機能 | 動作・設定 |
|---|---|
| `safewalk` | 接地中に足元の端を調べ、通常のスニークで落下を抑制。手動ジャンプを優先。`Edge margin`は0.05～0.4ブロック、既定0.12。部分ブロック・未確認の形状では保守的にスニークします。 |
| `durabilityguard` | 手持ちの道具・武器の残り耐久度が設定値を下回ると、同じ系統の予備へ切り替えます。ホットバーを優先し、予備が通常インベントリにしかなければ、手持ちスロットと交換します。素材違いの同系統も対象です。交換前の道具は予備があった場所へ残します。 |

AutoTool併用時は耐久保護の予備耐久も尊重し、消耗した元の道具への自動復帰を避けます。AutoEat・AutoFishの使用中や手動右クリック中は、耐久保護による持ち替えを見合わせます。チャット・L・ポーズでは停止し、SafeWalkのインベントリ中の継続はInventoryMoveの`Continue movement helpers`に従います。

耐久保護の設定値は**残り耐久度**です。例えば`set durabilityguard 50`は残り49以下で発動します。設定範囲は1～65535、既定10。候補は設定値以上の耐久がある同系統の道具で、ホットバー優先、同一ID優先、その後は素材と残り耐久で選びます。ツルハシ・斧・シャベル・クワ・剣を別系統とし、釣り竿・弓などもそれぞれ別に扱います。予備がない場合の空きスロット退避は追加オプション（既定OFF）です。

`guarddebug`は直前の判断・読み取った耐久・候補スロット・選択結果を表示し、DLLの隣の`Mio_Client_guarddebug.txt`にも保存します。Lを開いて停止しても、直前の判断が残ります。詳細設定のDiagnosticsにも同じ診断を表示します。通常インベントリからの交換はゲーム標準の要求・予測・変更通知経路を通し、NBT等を含むItemStackはゲームのコピー・破棄関数で扱います。

実装と検証の詳細はSafeWalkの記録（ローカルの`analysis/reports/safewalk_durability_guard_2026-11-16.md`）と耐久保護の更新記録（ローカルの`analysis/reports/durability_guard_inventory_2026-11-16.md`）にあります。

<a id="features-所持品装備移動の記録"></a>

### 所持品・装備・移動の記録

攻撃補助には、照準先だけを攻撃する **TriggerBot**（`toggle triggerbot`）を追加しています。
KillAuraには視野角・壁判定・左ボタン長押し限定の設定があります。使い方は[攻撃設定](#usage-triggerbotkillauraの攻撃設定)を参照してください。

以下の所持品・装備・移動記録機能は初期OFFです。Lで名前を検索するか、`toggle <名前>`で有効にできます。ESPは分類を詳細設定で設定します。

| 名前 | 動作・詳細設定 |
|---|---|
| `deathpoint` | HPが正値から0へ変わると死亡位置をウェイポイントへ保存。保存数1～16。自動マーカーだけを入れ替え、手動登録は残します。WaypointsがOFFでも死亡マーカーを描画します。 |
| `sessionstats` | 水平移動距離・最高速度・上向きの離地回数・ワールド内時間を集計。ワールド/ディメンション切替、長い停止、60 blocks/sを超える不連続移動は距離に加えません。リセットキーを設定できます。 |
| `esp` の分類 | プレイヤー／友好・中立／敵対／その他の表示切替と分類ごとのRGB。バニラ識別名で分類し、未知・アドオンは「その他」。中立モブの現在の敵対状態は判定しません。 |
| `armorhud` | 防具4部位の識別名・残り/最大耐久値・割合。画像アイコンではなく文字表示です。 |
| `inventoryhud` | アイコン・個数・耐久バーを9列のスロットに表示。通常インベントリ27スロットとホットバー9スロットを配置します。ホットバーだけの表示や、従来の文字一覧にも切り替えられます。 |
| `autotool` | 採掘ボタンを押している間、照準先のブロック種別に応じてホットバーのツールを選択。回収に必要な素材段階と残り耐久値を判定します。エンチャント・効果・アドオンの破壊速度は比較しません。 |
| `mininghud` | 採掘中のブロック名・ゲーム内の破壊進捗・任意の座標をHUDに表示。待機中は既定で非表示。 |
| `itemcounter` | 指定したアイテムと手持ちアイテムの合計所持数を表示。ホットバー限定、所持数0の非表示、対象ID編集に対応。 |
| `autoeat` | 空腹値が設定以下なら、ホットバーの通常食料を選んで通常の使用処理で食べます。金リンゴ・腐肉などは使いません。空中を向き、近く6ブロック以内に他のエンティティがいないときに開始します。 |

AutoEatを優先し、食事中はAutoToolの切替とKillAura・連続クリックを止めます。メニュー・インベントリ・フォーカス喪失・OFFで自動操作を解除し、現在の選択が自動操作のスロットのままなら元へ戻します。手動のスロット変更は優先され、再試行まで3秒待ちます。入力・スロット操作にキー送信は使いません。

AutoToolは最初の採掘処理より前に選択し、ボタンを押している間はブロック間の空気で元へ戻しません。スロット選択・復帰はゲーム自身のインベントリ選択関数で行い、結果を読み直して確認します。ホットバーに必要な道具がない場合は切り替わりません。`itemdebug`の最後の採掘判断は、一時停止で所持品データが期限切れになっても表示できます。

位置はHUDの配置を編集、数値・ON/OFFはプロファイルに保存できます。`itemdebug`でホットバー・防具・耐久値・自動操作の状態を確認できます。死亡地点は既存のウェイポイントと同じくディメンション単位で、ワールドをまたいで共有されます。既に死亡画面にいる状態からONにした場合は記録しません。

メモリ配置と検証手順はanalysis/notes/items.md（ローカルの`analysis/notes/items.md`）、実行ファイルを変更しない検証は`python analysis/tools/verify_items.py`です。

<a id="features-インベントリをhudに表示"></a>

#### インベントリをHUDに表示

Lで**InventoryHUD**をONにするか、コンソールで`toggle inventoryhud`を実行します。
インベントリを閉じた状態で所持品を表示し、ゲーム内の画面では通常のHUDと同じく非表示になります。
アイコン表示は通常インベントリが上3段、ホットバーが最下段です。空きスロットも保持し、同じアイテムの別スタックを合計せずに表示します。
複数個のスタックには個数、耐久がある道具には残り耐久のバーを表示します。

詳細設定では以下を調整できます。変更と表示位置はプロファイルに保存します。

- 「スロットを画像で表示」: OFFにすると、名前別に合計する従来の文字一覧へ戻ります。
- 「スロットの大きさ」: 28～64px、既定40px。
- 「スタックの個数」「耐久バー」: 個別に表示を切り替えます。
- 「ホットバーだけを表示」: 最下段の9スロットだけにします。
- 「文字一覧の最大行数」: 文字一覧モードで使用します。
- 表示位置: 横・縦位置、または「HUDの配置を編集」で移動できます。

画像は実行中のMinecraftに同梱されたバニラのリソースから読み込み、初期化時に1枚のアトラスへまとめます。
道具・食料は画像、通常の立方体ブロックは上面・側面のテクスチャを使って描画します。
画像を取得できないアイテムも、そのスロットに短い名前と個数を表示します。
サーバー・ユーザーのリソースパック、特殊モデルの完全再現、エンチャントの光沢、NBTによる色や模様の違いには未対応です。
所持品の読み取り処理は既存のものを使い、アイテムの移動・操作は行いません。

<a id="features-ゲームが更新されたとき"></a>

### ゲームが更新されたとき

ビルド固有の機能（ブロック・エンティティ・所持品・入力の遮断など）は、起動時に実行中のゲームを次の3段階で判定します。結果はコンソールに出ます。

| 判定 | 条件 | 使える機能 |
|---|---|---|
| 解析済み | 1.26.6301.0 / 1.26.65.1（実行ファイルの識別値が一致） | すべて |
| 修正版（全確認） | 未解析だが、組み込みシグネチャがすべて見つかり、ビルド固有のアドレス7個もすべて実行時に求められて検証を通った | すべて |
| 修正版（読み取りのみ） | 組み込みシグネチャはすべて見つかったが、アドレスの一部を求められなかった | 読み取るだけの機能（ブロックESP・ミニマップ・状態HUD・所持品HUDなど）。入力の遮断・KillAura・AutoFish・FreeLook・InventoryMove・インベントリ操作・ホットバー選択は無効 |
| 対象外 | 見つからない組み込みシグネチャがある | ビルド固有の機能は無効（座標・HUDなどシグネチャだけで動く機能は従来どおり） |

アドレスは、それを参照する命令のシグネチャ、またはvtableの決まった位置が既知の関数を指すことから求め、vtableの位置・データ領域の位置を確かめてから使います。
構造体のフィールドオフセットは解析済みビルドの値のままなので、修正版で構造体が変わっていた場合は表示がおかしくなることがあります（メモリを読む前の範囲確認は常に行います）。

**Ping**はL → HUD → Ping、または`toggle ping`で有効にします。既定は2秒間隔で、Detailsから1〜10秒の範囲で変更できます。HUD位置は配置編集から、間隔・位置・ON/OFFはProfilesへ保存できます。Detailsには値の取得元と、サーバー一覧用Pingの直近20回の平均・最小・最大、測定回数・取得不可回数を表示します。無効時は受信の観測を外し、測定スレッド・ソケットを解放して、追加の送信を行いません。

表示は**実接続の往復時間**を優先します。ゲーム自身のUDP通信（送信の`sendto`と受信の`recvfrom`）を読み取り専用で観測し、RakNetの枠組みだけを読みます（中の暗号化されたゲームデータは読みません。こちらからは何も送らず、通信も変更しません）。ゲームの接続中Ping（`0x00`）とサーバーの応答（`0x03`）の時刻差があればそれを、ない間はゲームが送ったデータグラムとサーバーのACKの時刻差（ACKごとに最も新しい送信との差、直近3秒の中央値。サーバーのACK待ち分だけ実際より少し大きめ）を使います。NetherNet（WebRTC）の接続では中身がすべて暗号化されていますが、ICEの接続確認（暗号化されないSTUNのBinding要求と、同じトランザクションIDの応答）が数秒ごとに行われるので、その時刻差（直近15秒の中央値）を使います。TURN中継経由（ChannelData・Send/Data indication）も1段だけ展開して読み、中継サーバー自体への要求は数えません。受信の観測はPingが有効な間だけ行います。Detailsには観測した件数（受信・送信・ACK・STUNの一致数）も表示します。

実接続の値がない間（接続直後など）は、[RakNetのUnconnected Ping/Pong](https://github.com/facebookarchive/RakNet/blob/master/Source/RakPeer.cpp)を別のUDPソケットで往復させた**サーバー一覧RTT**で補います。実接続の値が取れている間はこの送信を止めます。大型サーバーのロビー転送後など、サーバー一覧用Pingに応答しない接続先もあります（その場合は実接続の値だけを表示します）。接続先は既存のUDP通信から検出し、シングルプレイなど接続先がない場合は待機します。通信の待機は専用スレッドで行い、Timerによる時計の倍率変更を除いた高精度カウンターで計測します。接続先の変更・切断では過去の数値を破棄します。

表の各機能は、初期ONと明記したもの以外は初期OFFです。キー欄が「なし」の機能は未割り当てです。L メニュー、`toggle <名前>`、
または設定ファイルの `enabled = true` / `key = "..."` で有効にします。

`autosprint` / `autowalk` / `autosneak` / `autojump` / `autoswim` / `autoclicker` は 1.26.6301.0 / 1.26.65.1 x64 の内部処理を使用します。

`autowalk` と `autosneak` は初期OFFです。Lのチェックボックス、または
`toggle autowalk` / `toggle autosneak` で切り替えます。詳細設定で一時停止条件とキーを設定でき、プロファイルに保存できます。
AutoWalkの「Pause while moving backward」は既定ONで、通常の後退入力中だけ自動前進を解除します。
AutoSneakの「Only while moving forward」は既定OFFで、ONにすると前進入力中だけスニークします。
AutoWalkとAutoSprintは併用できます。スニーク中はゲームの通常動作に従ってダッシュ・自動ジャンプを止めます。
メニュー・チャット・インベントリ・非フォーカス時は自動入力を止め、OFF時は自動で加えた入力だけを解除します。
速度や座標を書き換えず、キーイベントも送信しません。

`autojump` と `autoswim` も初期OFFです。`toggle autojump` / `toggle autoswim`、またはLで切り替えます。
AutoJumpは既定で前進かつ接地中だけジャンプし、詳細設定の「Only while moving forward」をOFFにすると静止中も着地ごとにジャンプします。
AutoSwimは頭が水中にある間だけ通常の上昇入力を保持し、水から出ると解除します。溶岩や空中では作動しません。
どちらもスニーク入力中は停止し、手動Space入力を維持します。AutoSwimの「Only while moving forward」は既定OFFです。
既存のAutoSprintジャンプと入力所有を共有し、いずれか1機能をOFFにしても、別の機能が必要としているジャンプは継続します。
autosprint はゲームの移動状態を参照し、標準のスプリント押下・解放処理を呼ぶため、W や Ctrl の割り当てに依存しません。
前進（斜め前を含む）中に走る要求を追加し、後退・しゃがみ中は追加しません。空腹などゲーム側の制限は残ります。
初期設定では接地中だけ通常のジャンプ入力を加え、離陸時に解除し、着地すると再びジャンプします。
`[auto_sprint] jump = false` でジャンプを無効にできます。手動のジャンプ入力は保持します。
旧設定の `forward_key` / `sprint_key` は不要です（残っていても無視されます）。
autoclicker はゲームの攻撃ボタンの押下・解放を取得し、照準先をゲーム側で判定する通常の攻撃処理を繰り返します。CPS の上限は入力更新頻度にも依存し、
停止したフレームの分をまとめて実行することはありません。
両機能はワールドのプレイ中だけ動き、メニュー・チャット・フォーカス喪失時に停止します。
停止中は左上の一覧に `(paused: 理由)` と出ます。
走行フラグや速度の直接変更は行いません。`sprinting` はゲーム側の実際の走行フラグです。
`inputdebug` で入力更新回数・攻撃回数・停止理由を確認できます（gate: 0=動作可能、1=停止、2=メニュー、3=非フォーカス、4=ゲーム内画面）。
解析内容とシグネチャ検証は analysis/notes/native_actions.md（ローカルの`analysis/notes/native_actions.md`） にあります。

`coordinates` はワールドの座標表示設定にかかわらず、左上のHUD一覧に `coordinates X Y Z`（足元のブロック座標）を表示します。
ワールドに入っていない間は `(no world)` になります。
Lメニューのチェックボックス、F9、`toggle coordinates` で切り替えられます。
`[coordinates] native_hud = true` にすると、Minecraft標準の座標HUDも強制的に表示します
（OFFまたはejectで標準の表示処理に戻ります）。
ワールド設定やディスク上のexeは変更しません。`[coordinates] enabled = false` で初期状態をOFFにできます。
指定された実行ファイルをRizinで解析した結果と、オフライン検証手順は
analysis/notes/coordinates.md（ローカルの`analysis/notes/coordinates.md`） にあります。

`esp` はオーバーレイに枠線を描くだけで、ゲーム側のデータは書き換えません（`[gui] enabled = false` では使えません）。
`[esp] show_small = true` でドロップアイテムや矢などの小さなエンティティも表示し、
`max_distance` で表示距離（ブロック、0で無制限）を絞れます。
インベントリなどの画面を開いている間と、ワールドに入っていない間は表示されません。
調査内容は analysis/notes/esp.md（ローカルの`analysis/notes/esp.md`） にあります。

`fly` の速度は `set fly <blocks/s>` かメニューのスライダーで変えられます (1-100、既定10)。
移動キーは既定の割り当て (W/A/S/D、Space、Shift) を前提にしています。
`[esp] tracers = true` で、画面下端の中央から各エンティティへ線を引きます。
線を引く対象は種類ごとに選べます（詳細設定の「線: プレイヤー」「線: 敵対モブ」「線: 中立モブ」「線: 友好モブ（味方）」「線: その他（アイテムなど）」、設定ファイルでは `tracer_players` / `tracer_hostile` / `tracer_neutral` / `tracer_passive` / `tracer_other`）。既定ではその他以外の4種類に線を引きます。種類の判定はレーダー・ミニマップと同じで、枠の色分け（友好・中立は同じ色）とは別に、中立モブを区別します。

`fly` はプレイヤーの速度を書き換えます。シングルプレイ向けで、サーバーでは位置を戻されたり、不正な移動として扱われたりします。

<a id="features-ズームとフルブライト"></a>

#### ズームとフルブライト

`zoom` を有効にすると、`[zoom] hold_key`（既定 C）を押している間だけ画面を拡大します。
倍率は `set zoom <倍率>` かメニューのスライダーで変えられます（1.5〜30、既定4）。
寄るときと戻るときは滑らかに切り替わります（既定200ms、詳細設定「切り替えの時間（ms）」または `[zoom] smooth_ms`、0で瞬時）。倍率の対数で補間するので一定の速さで寄って見え、感度を下げる設定もズームの進み具合に合わせて変わります。

ZoomのONはキー入力を待つ状態です。Cを離すと視野角が1倍へ戻り、機能自体のON表示は維持します。
ZoomにはON/OFF用の「切り替えキー」はありません。詳細設定の先頭にある「ズーム中に押すキー」で、押している間だけ拡大するキーを指定します。旧設定・旧プロファイルのZoom用切り替えキーは無視し、ON/OFFはメニューのスイッチまたはコマンドで変更します。
補間はキー操作からの経過時間で求め、視野角の呼び出し回数やスレッド数に依存しません。
視野角・感度の取得時にもキー離し、非アクティブ、メニュー表示、入力更新の停止を確認します。
`viewdebug`では計算中の倍率とゲームへ最後に返した倍率、呼び出しの鮮度を別々に確認できます。
手に持ったアイテムの表示サイズは変わりません。初期設定では拡大中もマウス感度は変わらないので、視点は速く動いて見えます
（詳細設定 の `Reduce mouse sensitivity` で下げられます。後述）。
メニュー・チャット・インベントリを開いている間は拡大しません。

`fullbright` は、ゲームが明るさ設定を読む関数に高いガンマ値（`set fullbright <値>`、1〜25、既定10）を返させ、
暗い場所を明るく描画させます。保存される明るさ設定は変えません。
**描画モードが Vibrant Visuals のときは効きません**（このモードではゲーム自体が明るさ設定を描画に使わないため）。
Fancy モードでは効くことを確認しています。Simple モードは未確認です。

どちらもゲームの関数をフックして返り値だけを差し替えます。`viewdebug` コマンドで、
フックが呼ばれた回数とゲーム本来の値を確認できます。
関数の探し方と実機での確認結果は analysis/notes/visual.md（ローカルの`analysis/notes/visual.md`） にあります。

#### 視野角・照準先・軌跡（2026-11-14 追加、実ゲームでは未確認）

`fov` は `zoom` と同じ関数フックを使い、ワールドの描画に使う視野角を固定値にします（`set fov 140`、30〜170度、既定110）。
有効な間は、ダッシュや移動速度上昇による視野角の変化もこの値に置き換わります。保存される設定は変えません。
`zoom` と併用でき、その場合は固定した視野角をさらに倍率で割ります。手の表示サイズは変わりません。

到達距離は `set waila 12`（1〜64ブロック、既定6）で、ゲーム本来の届く距離より遠くも調べられます。

手前にブロックがあれば奥のエンティティを除外します。ブロックはボクセル単位、エンティティはコピー済みの当たり判定との交差で調べます。
ブロック ESP と同じ読み取り処理を使うため、1.26.6301.0 / 1.26.65.1 専用です。

保持する点の数は `set breadcrumbs 1000`（50〜3000、既定600）。48ブロックを超える瞬間移動
（テレポート、リスポーン、ディメンション移動）があると、そこから新しい経路として描き直します。

`coordinates` の 詳細設定「Portal coordinates」（`[coordinates] nether = true`）を有効にすると、
座標の後ろに `(nether X Z)`（ネザーにいる間は `(overworld X Z)`）を付けます。ネザーポータルの対応位置の計算用です。
ディメンションの判定は `dimension` と同じ読み取りを使います。確認済みなのはオーバーワールドの名前だけです。

blocks add *shulker_box    名前の末尾が一致するものすべて（* は前後の端に置けます）
blocks list                一覧
blocks del mob_spawner     削除（blocks clear で全削除）

名前は `/setblock` で使う名前から `minecraft:` を除いたものです。コマンドでの変更は eject までで、
常に使う名前は `[blockesp] extra = ["mob_spawner", "beacon"]` に書きます。最大32件。
読み取りの詳細は analysis/notes/blocks.md（ローカルの`analysis/notes/blocks.md`） にあります。

#### ミニマップ・軌道予測・フレーム時間（2026-11-17 追加、実ゲームでは未確認）

以下はテストとビルド、ゲームなしの描画確認まで行ったもので、実ゲームでの動作はまだ見ていません。
`minimap` と `trajectories` はブロック ESP と同じ読み取り処理を使うため、1.26.6301.0 / 1.26.65.1 専用です。

`minimap` は周囲の地形を上から見た地図で表示します。北が上で、白い矢印が自分の位置と向き、
点がエンティティです。色は `radar` と共通で、プレイヤーが緑、敵対モブが赤、中立モブ（オオカミ・ハチ・エンダーマン・ピグリン・アイアンゴーレムなど）が黄、友好モブが青、それ以外（アイテムなど）が灰色です。
種類はESPと同じエンティティ属性から判定します（解析済みビルドまたは修正版のときだけ。取得できないときは全て灰色）。
半径は `set minimap 48`（8〜64ブロック、既定32）、大きさ・エンティティ表示・位置は詳細設定かHUD編集で変えられます。
自分を中央に固定し、移動に合わせて地形を滑らかにずらします。固定をOFFにすると従来の列中央基準に戻ります。
4方位・現在のX/Z・地図の横幅（メートル）を表示します。詳細設定で座標と縮尺の表示をOFFにできます。
**チャンク境界を表示**で16ブロックごとの線を重ねられます。**エンティティの高度差**は0で無制限、数値を指定するとその高さの範囲内だけ表示します。
各列は上から下へ探し、最初に見えるブロック（地表）の色で塗ります。北側の列より高ければ明るく、低ければ暗く塗ります（バニラの地図と同じ考え方）。

#### ChatRepeat（指定文字列の繰り返し送信）

L → **ChatRepeat**をON → **Details**で本文・送信間隔・送信回数を設定 → **送信を開始** → Lを閉じます。
最初の送信も、画面を閉じてから指定した間隔だけ待って実行します。初期値は5秒ごとに10回です。

- 本文は改行なしの256文字以内。日本語を含む通常チャットに対応し、スラッシュコマンドは対象外です。
- 間隔は1～3600000ms（0.001～3600秒）。秒のスライダーに加え、**送信間隔（ミリ秒）**の数値欄と±ボタンでも調整できます。`250`なら250ms（0.250秒）です。実際の送信はゲームの更新周期に合わせて行い、指定時間の厳密な保証はありません。
- 回数は1～1000回。指定回数に達すると停止します。
- **送信を停止**または機能OFFで停止します。本文・間隔・回数を編集したときも停止し、再開には開始ボタンを使います。
- **通常チャットを開いている間も送信を継続**します。入力中の本文には触れず、チャット画面の通常更新中に送信します。
- Lメニュー・インベントリ表示中やゲームが非アクティブな間は一時停止します。画面を閉じると送信済み回数を維持し、残り回数を自動再開します。復帰後は改めて間隔を待ち、遅れた分をまとめて送信しません。
- ワールドやプレイヤーが変わった要求は実行せず、送信処理が失敗した場合も停止理由を表示します。
- 本文・間隔・回数・機能ON/OFFはプロファイルへ保存できます。間隔の保存形式は従来どおり秒単位で、ミリ秒の設定も保持します。設定読み込みやONだけでは送信を開始しません。
- 送信されない場合は`chatrepeatdebug`で待機条件・要求数・ゲーム側の受付結果を確認できます。診断は`Mio_Client_chatrepeatdebug.txt`にも保存されます（本文は記録しません）。

キーの疑似入力やクリップボード貼り付けは使わず、標準の通常チャット送信処理を使います。表示する件数はゲーム側が送信処理を受け付けた回数で、サーバー到着の確認ではありません。
実ゲームで指定回数の送信完了と、通常チャットを開いたままの継続を確認済みです。送信はユーザーの開始操作でのみ実行します。

**`chathud`**: 直近のチャットを、画面に常時表示するパネルに出します（既定は右下、HUD編集で移動）。
受信時刻（時:分）、送信者（名前ごとに決まった色。自分の送信は「自分」、送信者のないシステムメッセージは黄色）、本文の順に表示し、長い発言は幅で折り返します。
同じ人の同じ発言が続いたときは1行にまとめて「×3」のように回数を付けます。表示件数（1〜20、既定8）・幅・時刻の有無・表示秒数（0で常に表示）を詳細設定で変えられます。
ONにする前の発言は表示しません。

**`joinnotify`**: 送信者のないシステムメッセージから、プレイヤーの参加・退出を検出して通知します。
検出する文面はゲームの言語ファイル（日本語・英語）の「%sがゲームに参加しました」「%sがゲームを退出しました」「%s joined the game」「%s left the game」、名前変更時の形、Realm用の形です。
このセッションの入退室（直近100件）を詳細設定に新しい順で表示し、状態欄に参加・退出の回数を出します。
他の言語に設定している場合は検出しません。サーバーが独自の文面で入退室を知らせる場合も検出しません。

**`coords` コマンド**: 現在地（とディメンション）を表示します。`coords copy` は `X Y Z` をクリップボードへコピーします。

**ウェイポイントの拡張**:

- 追加したときのディメンションを記録し、そのディメンションにいる間だけ表示します。
  以前のファイルにある記録なしの地点は、これまでどおり常に表示します。`wp list` に記録が出ます。
- コンパス（`compass`）に、各ウェイポイントの方角を水色の印と名前の先頭3文字で表示します
  （詳細設定 の「Show on compass」、`[waypoints] compass`）。
- 詳細設定 の「Tracers」（`[waypoints] tracers = true`）で、画面下端の中央から各地点へ線を引きます。

**`blockesp` の拡張**:

- 左上の一覧に、最寄りの対象の種類と距離を表示します（`12 blocks, nearest diamond 14 m`）。
- 詳細設定 の「Tracers」（`[blockesp] tracers = true`）で、近い順に最大12個へ線を引きます。

<a id="features-表示系モジュール"></a>

#### 表示系モジュール

`fps` `cps` `speed` `direction` `clock` `memory` `entities` `server` は、有効にすると左上の HUD 一覧に
1行ずつ値を表示するだけのモジュールです。ゲームのデータは書き換えません。

- `cps` は実際のマウス操作を数えます。autoclicker が実行した攻撃は含みません。
- `speed` `direction` はワールド内でだけ値が出ます（それ以外は `(no world)`）。
  方角は S = +Z、W = -X、N = -Z、E = +X です。
- `entities` はエンティティの取得を動かし続けるため、ESP と同じく 1.26.6301.0 / 1.26.65.1 向けです。

`keystrokes` は W/A/S/D・Space・左右のマウスボタンを表示し、押している間は明るくなります。
マウスボタンには直近1秒のクリック数が出ます。既定のキー割り当てを前提にしています。
位置は `[keystrokes] x` / `y`（左上からのピクセル数。負の値は右端・下端から）で変えられ、既定は左下です。
ワールドの画面でだけ表示します。

`waypoints` は保存した地点に、壁越しに見えるマーカーと名前・距離を表示します。

```
wp add home            いまいる場所を home として保存
wp add mine 120 12 -340  座標を指定して保存（同じ名前なら移動）
wp list                一覧
wp del home            削除
```

地点は DLL と同じフォルダの `Mio_Client_waypoints.toml` に保存されます。
ワールドの区別はできないため、すべてのワールドで同じ一覧を使います。
ディメンションは追加時に記録し、同じディメンションにいる間だけ表示します（1.26.6301.0 / 1.26.65.1 でのみ判定できます）。
名前に空白は使えません（24文字まで、最大64件）。

`chunkborder` はカメラがいるチャンクの境界を描きます。四隅の柱は青、4ブロックごとの柱と
8ブロックごとの水平線は黄色で、カメラの上下32ブロックの範囲を描きます。
オーバーワールドでそのチャンクがスライムチャンクなら線を緑で描き、状態欄に「スライムチャンク」と出します。

`waypoints` と `chunkborder` は ESP と同じカメラ情報を使うため、対応ビルドやアップデート時の扱いも ESP と同じです。

実機（1.26.6301.0、シングルプレイ）で、`speed` `direction` `entities` の値、`keystrokes` の表示、
`chunkborder` の線、`waypoints` のマーカーが保存した座標の方向に出ることを確認しました。
`cps` のクリック計数と `server` のサーバー接続中の表示は未確認です。

### コンソールコマンド

`help`でコマンドの一覧、`list`で各機能のON/OFFと現在の状態を確認できます。
入力はCtrl+A / Ctrl+C / Ctrl+X / Ctrl+V、履歴全体は**ログをコピー**に対応します。

| 診断コマンド | 確認する内容 |
|---|---|
| `inputdebug` / `invdebug` | 通常入力・インベントリ移動の判定と実行回数 |
| `blockdebug` / `auradebug` | ブロック探索・攻撃対象と回数 |
| `triggerdebug` | `auradebug`と同じ。KillAura／TriggerBotの動作元・対象・共通の実行回数 |
| `fishdebug` | 釣りイベント・回収/再投要求・インベントリ中の使用回数 |
| `chatrepeatdebug` | 繰り返しチャットの待機理由・要求数・受付回数 |
| `worlddebug` | 時刻・天気・光量・FreeLookの取得値と状態 |
| `actordebug` / `statusdebug` | HP・食料・経験値、効果・酸素 |
| `itemdebug` / `guarddebug` | 所持品・道具選択、耐久保護の直前の判断と交換結果 |
| `viewdebug` | 視野角・明るさのフック。キー状態・計算倍率・最後にゲームへ返した倍率を分けて表示し、`Mio_Client_viewdebug.txt`へ保存 |
| `sdk` / `sdk chat` | SDKのプレイヤー状態・送信/受信チャット履歴 |
| `sdk watch <種類\|all>` / `sdk inspect` / `sdk unwatch` | SDKの追加情報を購読・確認・解除。inspectは`Mio_Client_sdkdebug.txt`へ保存 |
| `gamedebug` | 取得中のゲーム・クライアント・プレイヤーのアドレス |
| `compatdebug` | PEの識別情報、名前付きシグネチャの一致数、基本互換性とスキン配置の検証結果 |
| `profilerdebug` | PerformanceProfilerの直近の集計結果を表示し、`Mio_Client_profiler.txt`へ保存 |
| `skindebug` | SkinStealerの取得対象・画像サイズ・保存状態（診断ファイルも保存） |

`fishdebug`・`guarddebug`・`gamedebug`はDLLの隣にも診断ファイルを保存します。
アドレスは現在のプロセスにだけ有効で、再起動後には取得し直します。

ゲーム更新後は`compatdebug`を実行すると、DLLの隣に`Mio_Client_compatdebug.txt`を保存します。
`MISSING`は未検出、`CANDIDATES`は複数候補です。`MATCH`も命令の一致を示すだけで、ABIや動作の保証ではありません。
基本機能と任意の読み取り機能を分けて判定し、スキンの元画像取得とモデル変換も別々に検証します。

`toggle skinstealer`で一覧を取得し、`skins list`で対象を表示します。`skins save self` / `skins save <一覧の16進ID>`はスキン用PNGをDLLの隣の`skins`へ保存します。対応Personaは顔画像とUVから64×64または128×128（幅広の腕）へ変換します。`skins raw self` / `skins raw <ID>`は元のアトラスだけを保存します。ONにしただけでは保存しません。独自の立体形状には制限があります。

`radar` は画面右上に周囲のエンティティを表示します（初期ON）。上方向が視点の前方です。
`set radar 48` で水平の表示範囲を変更できます（8〜128ブロック）。点はMinimapと同じ種類別の色です（プレイヤー緑・敵対赤・中立黄・友好青・その他灰）。
位置・サイズは `[radar] x/y/size` で指定します。

`targethud` は KillAura が対象を攻撃している間、区分・距離・IDとセッションの攻撃／成功／腕振り回数を右下に表示します。
初期ONで、`toggle targethud` で切り替えられます。対応ビルドでは現在の表示名（空なら種類名）と現在／最大HP、HPバーも表示します。

`toggle vitals` で自分のHP・吸収HP・満腹度・隠し満腹度（Saturation）・消耗度（Exhaustion）・レベル・次のレベルまでの進捗を表示します。
`toggle nametags` で周囲の表示名・HP・距離を表示します。現在の名札メタデータを読み、プレイヤー名やカスタム名を反映します。
名前が空か取得できないときは `cow` / `player` などの種類名を使います。詳細設定の`Display names`をOFFにすると従来の種類名表示になります。
どちらも初期OFFです。Lの詳細設定で表示位置や対象、HP／距離の表示を変更し、プロファイルで保存できます。
NameTagsは既定48ブロック・最大32件で、近くの対象を優先します。`set nametags 64` で距離を変更できます。
共通データはゲーム側で10Hz取得し、ID世代・当たり判定・数値を検証します。取得できないHPは表示しません。`actordebug` で件数と自分の数値を確認できます。

Zoomの詳細設定にマウス感度倍率を追加しました（初期OFF）。`Reduce mouse sensitivity` を有効にすると、ズームキーを押している間だけマウス用の感度設定値に倍率を掛けます。
既定倍率は0.25です。タッチ・コントローラーや保存済みの感度設定は変更しません。
感度設定値から実際の回転速度への変換は未検証のため、倍率と画面上の回転速度が正比例するとは限りません。
新しい属性取得と感度フックは1.26.6301.0 / 1.26.65.1 x64向けです。取得位置の根拠と確認範囲は analysis/notes/actors.md（ローカルの`analysis/notes/actors.md`） を参照してください。

`toggle crosshair` で追加の照準を表示します。`set crosshair 8` で線の長さを変更できます。
Lの詳細設定で隙間、太さ、中心点、黒い輪郭、T字形、RGB、透明度を設定します。
`Movement spread` は移動速度に応じて隙間を広げる見た目の設定で、ゲームの攻撃精度を示すものではありません。
元のゲームの照準に重ねて描画します。チャット・インベントリ・Lメニューでは非表示になります。

`toggle lowhealth` はHPが最大値の30%以下になったときに通知し、赤い画面外枠を出します。
`set lowhealth 40` なら40%です。閾値を5パーセントポイント上回るまで警報状態を維持し、回復後の再低下で再通知します。
同じ低HP状態が続く間は繰り返し通知しません。最低通知間隔は既定10秒で、間隔中の再低下は期限到来まで通知を待ちます。
詳細設定で通知・外枠・吸収HPを含めるか・通知間隔を変更できます。死亡後や数値が取得できない状態では警報を出しません。

`toggle playeralert` は読み込み済みの他プレイヤーを既定32ブロックの3次元距離で検出します。
`set playeralert 64` で範囲を変更できます。範囲内の人数と最短距離をHUDに出し、新規侵入を通知します。
境界の出入りで通知が連続しないよう、退出判定には2ブロックの余裕を設けます。その間は設定範囲より最大2ブロック外の対象も人数に含みます。
通知間隔は既定5秒です。間隔中に入った対象がまだ近くにいれば、期限後にまとめて通知します。
自分とモブは対象外です。読み込まれていないプレイヤーは検出できません。詳細設定でHUD・通知・位置・間隔を変更できます。

この3機能は初期OFFです。既存の入力や取得データを使い、新しいメモリ書き込みは追加していません。
Crosshairは最大20Hz、LowHealthは10Hz、PlayerAlertは5Hzで状態を更新し、表示は描画に追従します。
通知には共通の `[gui] notifications = true` が必要です。メニュー表示中と非フォーカス時は通知・表示を休止します。
各詳細設定はプロファイルで保存・復元できます。新機能の実ゲームでの表示・通知動作は未確認です。

`toggle effects` で効果一覧を表示します。例えば `Jump Boost I 6:38` のように名前・強さ・残り時間が出ます。
詳細設定で名前に併記する強さ・時間、表示位置、最大件数を設定できます。残り時間が短い効果を優先し、未知の名前は `Effect <ID>` と表示します。
`Expiry notification` をONにすると既定10秒以下の効果を一度だけ通知し、効果の更新・再付与で再通知できるようになります。通知間隔は最低2秒です。
時間は実際のゲームカウンタ（通常20 ticks/秒）から表示し、壁時計による残り時間の推測はしません。効果なしではパネルを隠します。

`toggle air` で酸素HUDを表示します。水中、または地上で回復中だけ表示するのが初期設定です。
詳細設定で常時表示、元のカウンタ値（`Raw ticks`）、位置を変更できます。バーは酸素量の割合で、溺れるまでの時間の予測ではありません。
この2機能も初期OFFで、詳細設定はプロファイルに保存できます。Lなどの画面が開いている間は表示・通知を休止します。
`statusdebug` で取得中の効果ID・強さ・残りticksと、現在／最大の酸素量を確認できます。
効果・酸素・名札の取得はゲームスレッドで10Hz、表示側にはコピーだけを渡します。新しいネイティブ関数呼び出しやメモリ書き込みは追加していません。
1.26.6301.0の実メモリで効果と酸素量の変化を確認済みです。更新したHUDの描画は未確認です。解析根拠は analysis/notes/status.md（ローカルの`analysis/notes/status.md`） にまとめています。

<a id="commands-プロファイル"></a>

### プロファイル

Lメニュー上部の「プロファイル・保存」で、名前を入力して「保存」、保存済みの名前を選んで「読み込み」を押すと設定を切り替えられます。
「ファイルから読み込み…」では、Windowsのファイル選択画面で任意の場所のプロファイル（`.toml`、人から受け取ったものなど）を選んで読み込めます。選択画面はプロファイルの保存先から開きます。読み込んだファイルは保存先へコピーしないので、一覧に加えたい場合はそのまま「保存」してください。
保存対象は機能のON/OFF、切り替えキー、数値、詳細設定内の対象選択・表示位置などです。
設定は変更直後に反映されます。再起動後に戻すには保存したプロファイルを読み込みます。
従来のプロファイルも読込可能で、記録されていない詳細設定は現在の値を維持します。
起動時の初期値は引き続き `Mio_Client.toml` で指定します。
ファイルは DLL と同じフォルダの `profiles/<名前>.toml` に保存されます。コマンドでも操作できます。

```text
profile save explore
profile load explore
profile import "D:\Downloads\pvp setting.toml"
profile list
```

### 詳細設定

各機能の **詳細設定** で調整できる項目（代表例）:

| 機能 | 詳細設定 |
| --- | --- |
| 全機能 | 切り替えキー（切り替えキー。NONEで解除） |
| autosprint | 接地時の自動ジャンプ |
| autowalk / autosneak | 後退操作中の一時停止 / 前進中だけスニーク |
| autojump / autoswim | 前進中だけジャンプ / 前進中だけ自動浮上 |
| inventorymove | ジャンプ・スニークの許可、自動移動の継続、移動キーの割り当て |
| autoclicker / timer / fly / fullbright | CPS / 時間倍率 / 移動速度 / 明るさ |
| killaura | 射程、CPS、プレイヤー・モブを対象にするか |

| radar | 探索範囲、表示サイズ、X・Y位置 |

| compass | 幅、Y位置 |
| zoom | 倍率、押している間ズームするキー |
| coordinates | Minecraft標準の座標HUD表示 |

メニューを開いている間はモジュールのホットキー切り替えを停止するため、検索・プロファイル名の入力で誤作動しません。
各設定にマウスを合わせると説明が出ます。保存・読込時は型と範囲を検証し、適用失敗時は以前の設定へ戻します。

`killaura` は射程内のモブ・プレイヤーを近い順に、1周期あたり最大8体まで自動攻撃します。初期状態はOFF。
`toggle killaura` で有効化し、`set killaura 3` で射程を変更します（1〜6ブロック、既定3）。
攻撃周期の頻度は `[killaura] cps`（既定8）、1周期の対象数は `max_targets`（既定8、1～16）、対象は `players` / `mobs` で設定します。
メニュー・チャット・インベントリでは停止し、有効中はオートクリッカーの繰り返しを休止します。
`auradebug` は対象数・攻撃回数・ネイティブ関数の成功回数を表示します。
解析記録は analysis/notes/combat.md（ローカルの`analysis/notes/combat.md`） です。

`compass` は画面上部中央に方位バーを表示します（初期ON）。`toggle compass` で切り替え、
`set compass 400` で幅を変更します。上下位置は `[compass] y`。
Minecraft の yaw に合わせ、0=S、90=W、180=N、270=E と表示します。

コンソール入力欄は Ctrl+A / Ctrl+C / Ctrl+X / Ctrl+V に対応します。
`ログをコピー` ボタンで表示履歴全体を Windows のクリップボードへコピーできます。
コピー・貼り付けは Unicode 対応です。貼り付けだけではコマンドを実行せず、Enter で確定します。

`blockesp` は周辺の読み込み済みブロックから鉱石とチェスト類を色別の枠で表示します。
L メニューまたは `toggle blockesp` で切り替え、`set blockesp 32` で探索半径を変更できます（4〜64、既定24）。
設定は `[blockesp]` の `ores` / `chests`。初期状態はOFFです。
探索と更新は分割されるため、範囲全体の表示には少し時間がかかります。
未読み込みチャンクやサーバーから送られていないブロックは対象外です。
解析記録は analysis/notes/blocks.md（ローカルの`analysis/notes/blocks.md`）、診断コマンドは `blockdebug` です。

```
list                  モジュール一覧と状態
toggle <module>       ON/OFF 切り替え
set <module> <value>  autoclicker = CPS (1-20), timer = 倍率 (0.1-10), fly = 速度,
                      zoom = 倍率 (1.5-30), fullbright = ガンマ (1-25)
viewdebug             zoom / fullbright のフックの呼び出し回数とゲーム本来の値
ip [all]              接続中のサーバーのアドレス / 直近の送信先一覧
wp list               ウェイポイント一覧（ワールド内なら距離も表示）
wp add <name> [x y z] 追加・移動（座標を省くと現在地）
wp del <name>         削除（wp clear で全削除）
blocks list|add|del|clear  blockesp に追加で表示するブロック名
bind <key> <command>  キーにコマンドを割り当て（bind list / unbind <key>）
coords [copy]         現在地を表示 / クリップボードへコピー

```

<a id="commands-接続先サーバーのアドレス"></a>

#### 接続先サーバーのアドレス

コンソールの `ip` で、接続中のサーバーのアドレス（`IP:ポート`）を表示します。
`ip all` は直近3秒間に UDP を送った相手をすべて、1秒あたりのパケット数が多い順に表示します。

ゲームの内部データは読まず、WinSock の `sendto` / `WSASendTo` をフックして送信先を記録します
（実装は `client/src/net.rs`）。RakNet と NetherNet（WebRTC）のどちらも `sendto` を通るため、
通信方式やゲームのビルドに依存しません。1.26.6301.0 の実行ファイルが `sendto` をインポートし、
`WSASendTo` をインポートしていないことは確認済みです。

- 1秒あたり5パケット以上を送り続けている相手のうち、最も多い相手をサーバーとみなします。
  接続中の相手にはゲームの tick ごと（毎秒20回）に送るのに対し、LAN 内のワールド探索や
  サーバー一覧の ping は毎秒1回程度です。送信が3秒止まると対象から外れます。
- ゲームは IPv6 ソケットで IPv4 に送るため、宛先は `::ffff:a.b.c.d` の形で届きます。これは IPv4 に直して扱います。
- ループバック、マルチキャスト、ブロードキャストは除外します。サブネットのブロードキャスト
  （例: `192.168.0.255`）は、Windows から取得したネットワークアダプターの情報で判定します。LAN のアドレスは対象です。
- NetherNet の接続（フレンドのワールドなど）が中継サーバー経由の場合、表示されるのは中継サーバーのアドレスです。
- シングルプレイでは相手がいないため `no server detected` になります。
- 注入後に送信したパケットだけを見るので、注入・接続の直後は2秒ほど待ってから実行してください。

実機（1.26.6301.0）のメインメニューでは、LAN 探索のブロードキャスト `192.168.0.255:7551` だけが送られていて、
当初の「8パケット以上」という判定ではこれをサーバーと誤認しました。上記の判定はその修正です。
サーバー接続中の表示は未確認です。フックが実際の `sendto` の宛先を拾うことはテストで確認しています。

<a id="sdk"></a>

## SDK

クレート名`mcbe-sdk`と既存のRust APIは互換性のため維持しています。

Minecraft 内の Rust モジュール向け API です。ゲーム固有のポインタやオフセットを各モジュールで扱わず、状態のコピーとコマンドキューを使います。

| API | 内容 |
|---|---|
| `game.player()` | 足元座標・目の座標・速度ベクトル・視線の yaw / pitch |
| `player.speed()` / `horizontal_speed()` | 速度 / 水平速度（blocks/s） |
| `player.direction()` | 視線の単位ベクトル |
| `game.click()` | 通常の左攻撃・破壊入力を一度要求 |
| `game.set_velocity(Vec3)` | 速度ベクトルの設定要求（blocks/s） |
| `game.chat_since(cursor)` | 注入後に取得した送信・受信チャット本文 |
| `game.observe(Topic::Entities)` → `.entities()` | 自分を除く取得済みエンティティのID・種類・表示名・体力・当たり判定 |
| `game.observe(Topic::Inventory)` → `.inventory()` | ホットバー9＋通常27スロット、防具4部位、選択中スロット |
| `game.observe(Topic::Vitals)` → `.vitals()` | 自分の体力・吸収・空腹・隠し満腹度・消耗度・レベル・経験値 |
| `game.observe(Topic::Status)` → `.status()` | 効果のID・強さ・残りticks、現在／最大酸素量、水中判定 |
| `game.observe(Topic::World)` → `.world()` | ワールド時刻・経過日・雨・雷・ディメンション |
| `game.observe(Topic::Target)` → `.target()` | 照準先のブロック／エンティティ・距離。対象なしも区別 |

<a id="sdk-observations"></a>

### 読み取り情報の購読

`observe`はワーカーで一度呼び、返された`Observation`を更新の間も保持します。対応するHUDをONにする必要はありません。
最初のゲーム内サンプルが届くまでは`StaleState`、ワールド外は`NoWorld`です。購読を毎フレーム作り直さないでください。

```rust
use mcbe_client::api::{self, Game, Observation, Topic};

struct InventoryReader {
    inventory: Observation,
}
impl InventoryReader {
    fn new(game: &Game) -> api::Result<Self> {
        Ok(Self { inventory: game.observe(Topic::Inventory)? })
    }
    // 後の更新で呼びます。ネイティブメモリへ直接アクセスしません。
    fn update(&self) -> api::Result<()> {
        let inventory = self.inventory.inventory()?;
        println!("手持ち {:?}、パン {}個", inventory.held(), inventory.count("bread"));
        println!("防具 {:?}", inventory.armor);
        Ok(())
    }
}
```

- `.read()`で型付きデータと元のサンプルの経過時間`age_ms`を取得できます。型別メソッドは読み取り専用の`Arc`を返し、同じサンプルの変換結果を再利用します。
- 所持品の`selected`は**0始まり**です。`slots[0..9]`がホットバー、`slots[9..36]`が通常インベントリ、`armor`は頭・胴・脚・足の順。空きスロットは`None`を維持します。
- `Inventory::count("bread")`はホットバーと通常インベントリの合計です。`minecraft:`は省略可能で、防具・チェストは含みません。`ItemStack::remaining_durability()`は耐久値のない品物で`None`を返します。
- エンティティはID順で最大1,024件、自分を除きます。IDは世代込みですが、そのワールド内だけで有効です。体力や当たり判定を取得できない項目は`None`です。
- 効果の`amplifier=0`はレベルI、`ticks=None`は無限効果です。`effects=None`は取得できない状態、空の配列は効果なしを示します。
- 時刻は0ticksが06:00。`WorldInfo::clock()`で時分、`.day()`で経過日を得ます。酸素はゲームのカウンター値で、残り秒数ではありません。
- 照準先はWailaと同じブロック単位の走査・当たり判定を使い、手前のブロックで遮蔽します。読み取り距離・液体の扱いは共有の照準取得設定に従い、購読時には変更しません。`Ok(Arc::new(None))`相当は「取得成功・対象なし」で、未取得エラーと異なります。
- 属性・所持品・効果は約100ms、時刻・天気は約200msごとの既存サンプルを使います。照準先は共有走査の周期で更新します。呼び出し回数を増やしてもゲーム側の取得頻度は上がりません。
- 元のサンプルが古い場合は`StaleState`、読み取り途中のワールド変更は`WorldChanged`、終了後は`Detached`です。メニュー表示中でも新鮮なデータは読めますが、取得処理自体が止まれば期限切れになります。
- 購読は`drop`で解除し、使わなくなったサンプラーを解放します。開始・解除はワーカーで行い、取得済みデータの読み取りは複数スレッドから利用できます。購読上限は128件です。
- Runtimeの終了時は、保持中の購読も無効化して取得処理を解放します。解除が完了しなければ`shutdown()`は`false`を返し、次回の呼び出しで再試行できます。

従来の`player()`・`click()`・`set_velocity()`・`chat_since()`とコマンド形式は維持しています。
追加した6系統は読み取り専用で、道具の移動・攻撃・チャット送信などは行いません。

<a id="sdk-既存クライアント内から使う"></a>

### 既存クライアント内から使う

既存クライアントは Runtime を自動起動します。モジュールからは `api::game()` でハンドルを取得します。

```rust
use mcbe_client::api::{self, ChatDirection, Game, Receipt};

fn inspect(game: &Game, cursor: &mut u64) -> api::Result<()> {
    let player = game.player()?;
    println!("位置 {:?}、水平速度 {}、向き {:?}",
        player.position, player.horizontal_speed(), player.direction());

    let batch = game.chat_since(*cursor)?;
    if batch.missed {
        println!("古いチャットは保存上限を超えて破棄されました");
    }
    for message in batch.messages {
        let label = match message.direction {
            ChatDirection::Sent => "送信",
            ChatDirection::Received => "受信",
        };
        println!("[{label}] {}", message.text);
    }
    *cursor = batch.cursor;
    Ok(())
}

fn attack_once() -> api::Result<Receipt> {
    api::game()?.click()
}
```

`Game` は Clone 可能で、描画・モジュール・ワーカースレッドから使えます。`player()` は直近のコピーを返し、ネイティブオブジェクトの参照は返しません。
角度は度、yaw=0 は +Z、yaw=90 は -X、pitch は下向きが正です。

`click()` と `set_velocity()` は非同期です。返された `Receipt` の `status()` が `Completion::Done` になれば、ゲームの入力更新スレッドで処理済みです。
これは入力要求の実行完了を意味し、命中やサーバーの受理を保証するものではありません。ゲームスレッド上で待機しないでください。
メニュー表示中などは `Paused`、ワールド外は `NoWorld`、状態更新が止まれば `StaleState` を返します。
未処理要求は 500ms で失効し、ワールド切替・終了時にも取り消されます。キューは最大 128 件です。

速度設定は移動成分の直接変更です。通常のダッシュは既存の autosprint を使ってください。サーバーが移動を補正する場合があります。

<a id="sdk-チャットの範囲"></a>

### チャットの範囲

- 送信は、本文がゲームの通常チャット送信処理に渡された時点です。サーバーの配信確認ではありません。スラッシュコマンドは別経路のため対象外です。
- 受信は、ゲームがチャット履歴へ追加するレコードの本文です。システム通知・書式コードを含む場合があります。`sender` はレコードの送信者文字列で、値がない場合は `None` です。名前にも書式コードが残る場合があります。
- 自分の送信内容がチャット欄に戻ると、`Sent` と `Received` がそれぞれ記録されます。
- 注入後の最大 512 件を保持します。カーソル初期値は 0。返された `cursor` を次回へ渡してください。複数の読者で独立して読めます。
- 入力中の下書きや、注入前の履歴は取得しません。本文は UTF-8 の所有文字列としてコピーし、1 本文は最大 32KiB です。

<a id="sdk-自分の-dll-に組み込む"></a>

### 自分の DLL に組み込む

Windows x64 のゲーム内プロセスで使う Rust ライブラリです。外部プロセスや Python から呼ぶ ABI は提供していません。

```toml
[dependencies]
mcbe_client = { package = "client", path = "D:/Programming/Rust/Mio_Client/client", default-features = false }
```

自分の DLL のワーカースレッドで `unsafe { api::Runtime::attach(&api::Offsets::default()) }` を一度だけ呼び、Runtime を保持します。DllMain からは呼ばないでください。
終了時は `runtime.shutdown()` が `true` を返してから DLL をアンロードします。`false` の場合はフックが残るため DLL を保持してください。既存クライアントのモジュールからは追加の attach は不要です。

ネイティブのクリック・チャット経路は Minecraft Windows 1.26.6301.0 x64 向けです。対応しない場合は `Unavailable` を返します。
純粋な `mcbe-sdk` crate は OS に依存しない状態・キュー部分で、`client::api` が実ゲームとの接続を担当します。

組み込み例: [client/examples/sdk_module.rs](client/examples/sdk_module.rs)

```powershell
cargo test --workspace --offline
cargo build -p client --example sdk_module --offline
cargo check -p client --no-default-features --offline
cargo run -p mcbe-sdk --example read_state --offline # 模擬バックエンド
```

ゲーム内コンソールでは `sdk` で現在の状態、`sdk chat` で直近 20 件を確認できます。
新しいAPIは`sdk watch all`（または`inventory`等の種類名）で購読し、Lを閉じて取得を待ち、`sdk inspect`で値を確認します。
`sdk inspect`はDLLの隣の`Mio_Client_sdkdebug.txt`にも保存します。`sdk unwatch`で診断用の購読を解除します。
SDK単体のホストでは`bridge::ObservationBackend`・`ObservationSource`を実装し、`Bridge::set_observation_backend`で接続できます。
バックエンド未提供の既存ホストも従来APIは動作し、`observe`だけが`Unavailable`になります。

<a id="development-実行フロー"></a>

### 実行フロー

1. `client/src/lib.rs`の`DllMain`がワーカースレッドを開始し、`client::run`へ移ります。
2. DLLの隣の設定を読み込み、機能レジストリ・プロファイル・キー割り当てを生成します。
   `api::Runtime::attach`がゲーム側の取得処理・通常入力・チャットをSDKへ接続します。
3. ゲームスレッドのフックがメモリ配置・値の妥当性を確認してサンプリングします。
   必要な機能が購読しているデータだけを更新し、表示側へコピーまたは読み取り専用の共有スナップショットを渡します。
4. ワーカーループがコンソールのコマンド、ホットキー、各機能の`tick`を処理します。
   自動操作の要求はゲーム側の入力処理で消費し、画面状態・有効期限・対象の生存を再確認します。
5. `gui.rs`の描画処理がメニューと各機能のオーバーレイを表示します。
6. eject時は自動操作を解除して各フックの終了を確認します。解除完了時だけDLLを解放し、
   描画フックがある場合はhudhookの次フレームで解放します。後処理が残る場合は無効化した状態で保持します。

SDKの公開型・APIは`mcbe-sdk`、ネイティブ接続の実装は`client::api`と`modules::game`に分かれています。
`client`を`default-features = false`で使う場合は`DllMain`と組み込みワーカーループを含めず、呼び出し元がRuntimeの寿命を管理します。

<a id="development-変更と検証"></a>

### 変更と検証

ゲーム固有の署名は`client/src/signatures.rs`へ用途コメント付きで追加します。
同ファイルの`catalog!`を名前付きの登録元とし、起動時の共有走査と`compatdebug`で共用します。
新しい任意の読み取り機能は基本互換性から切り離し、自分の署名・配置・ABIを検証します。
ワイルドカード化したフィールドは命令から取得し、一意性と複数の利用箇所を照合してください。
一致した最初の候補を採用したり、署名の一致だけで未知のABIの呼び出しを許可したりしません。
配置・寿命・検証の根拠は`analysis/notes/`へ、作業結果と計測条件は`analysis/reports/`へ記録します。
検証スクリプトは`analysis/tools/`、単体の計測コードは`analysis/benchmarks/`に置きます。
ビルド手順と通常の確認コマンドは[ビルドガイド](#build)、解析ツールの入口は解析資料の索引（ローカルの`analysis/README.md`）です。

`dll-oss-main/`と`Microsoft.MinecraftUWP_*/`は参照用で、Cargoのメンバーには含めません。
`.analysis-cache/`はローカルのバックアップ・生データ、`target/`は成果物です。
実行時設定が成果物フォルダへ保存される点は[出力先の説明](#build)を参照してください。

<a id="development-参考にしたクライアント"></a>

#### 参考にしたクライアント

追加機能の選定には Flarial Client（AGPL-3.0）のモジュール一覧を参考にしました。コードは流用していません。
同クライアントの公開シグネチャ 480 個を 1.26.6301.0 の実行ファイルに当てたところ、一意に一致したのは 11 個で、
視野角（ズーム）・明るさ・マウス感度・ping に関するものはすべて不一致でした。
そのため視野角・明るさ・マウス感度の取得関数は、このビルドで独自に探し直しています
（analysis/notes/visual.md（ローカルの`analysis/notes/visual.md`）、analysis/notes/actors.md（ローカルの`analysis/notes/actors.md`））。ping はまだ特定していません。

<a id="development-ゲームのアップデートについて"></a>

#### ゲームのアップデートについて

`coordinates` と `esp` は 1.26.6301.0 で調査したものですが、別のビルドでも動くように、
ゲームのコードから読み取れるオフセットは起動時に読み取ります（注入時のログの `game:` の行に出ます）。
読み取れない値は `Mio_Client.toml` の `[offsets]` で上書きできます。
値が合わない場合は機能が無効になるだけで、ログに理由が出ます。解析済みビルドは1.26.6301.0 / 1.26.65.1です。その他のビルドは[更新時の判定](#features-ゲームが更新されたとき)に従います。

<a id="branding-既存環境からの利用"></a>

### 既存環境からの利用

`mcbe_injector_gui.exe`もMio Launcherと共通の実装を使い、同じ画面を開きます。
`mcbe_injector.exe`のCLI、プロファイル、SDKのクレート名（依存関係の名前`mcbe_client`）は互換性のため維持します。DLL・設定・診断ファイルは`Mio_Client`の名前に統一しました。
設定のキー・機能ID・ネイティブの解除イベントも同じです。名前変更に伴う設定の移行操作は不要です。

ビルドは`cargo build --release --workspace`、起動は`target/release/mio_launcher.exe`です。
`cargo run -p injector`でもMio Launcherを起動できます。

<a id="project-layout"></a>

## プロジェクト構成

| 場所 | 役割 |
|---|---|
| `client/` | ゲームへ注入する`Mio_Client.dll`、機能・HUD・ネイティブ接続 |
| `injector/` | `mio_launcher.exe`、従来のGUI/CLI、起動・注入・解除・署名照合 |
| `signature_checker/` | オフラインのシグネチャ検証EXE（GUI/CLI）、PE読み取り、JSON比較 |
| `shared/branding.rs` | Mioの名前・配色・ロゴ形状。ゲーム内UIとランチャーで共用 |
| `shared/compatibility.rs` / `shared/skin_layout_checks.rs` | クライアントと検証EXEが共用するアドレス導出・フィールド整合性の判定 |
| `sdk/` | 公開ライブラリ`mcbe-sdk`、状態スナップショット・コマンド・チャット |
| `sigscan/` | シグネチャスキャンとPE解析ライブラリ |
| `docs/` | ローカルに保持する旧ドキュメントの案内（Git管理対象外） |
| `analysis/notes/` | 機能別の解析根拠 |
| `analysis/reports/` | 日付付きの変更・計測記録 |
| `analysis/tools/` | 検証・調査用Pythonツール |
| `analysis/benchmarks/` | 再現用ベンチマーク |
| `analysis/fixtures/` | 調査時の固定データ |
| `.vscode/` | Rustワークスペースの設定、ビルド・テスト・Lintタスク |
| `target/` | ビルド成果物とローカルの実行用ファイル |
| `.analysis-cache/` | ローカルの作業前バックアップ・計測ログ |
| `Microsoft.MinecraftUWP_*/` | 解析対象のゲームパッケージ（Rustワークスペース外） |
| `dll-oss-main/` | Flarialの参照資料（Rustワークスペース外） |

初期設定のテンプレートは[client/default_config.toml](client/default_config.toml)です。

DLL・設定・診断ファイルは`Mio_Client`の名前です。旧名の`mcbe_client.toml`・`mcbe_client_binds.toml`・`mcbe_client_waypoints.toml`・`mcbe_client_windows.toml`は、新しい名前のファイルがない場合に初回起動時にコピーして引き継ぎます（旧ファイルは残すため、古いDLLに戻しても設定は使えます）。SDKのクレート名（依存関係の名前）は維持しています。設定・プロファイルの移行操作は不要です。
実行時の設定・プロファイル・ログはDLLと同じフォルダへ保存します。
生成物を整理するときも、使用中のDLLと保存した設定は保持してください。
